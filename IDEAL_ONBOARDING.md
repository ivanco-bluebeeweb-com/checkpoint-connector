# Check Point Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь:
network/security admin, управляющий Check Point gateways через один
Security Management Server (или Multi-Domain Server).

## 1. Credential type

Одна форма: `host` (напр. `https://mgmt.company.com`) + `username` +
`password` + опционально `domain` (только для Multi-Domain Security
Management — оставить пустым для обычной инсталляции). Коннектор
обменивает их на session id (`sid`) через `login` при подключении и
хранит только `sid`-получающие креды, не сам сохранённый sid долгосрочно
(sid короткоживущий, перелогин прозрачен при истечении).

## 2. Идеальный флоу

1. **Первое открытие** — `Empty` с одной формой подключения (не визард
   из нескольких путей, в отличие от Fortinet/PAN-OS — здесь только один
   тип сервера).
2. **Форма подключения** — `host` + `username` + `password` + `domain`
   (необязательное). Подсказка (в help-модалке): где взять права
   (администратор с ролью, дающей доступ к Web Services / API), что
   делает коннектор при подключении (login-обмен, session id хранится
   временно), и что такое `domain` (только для Multi-Domain Server,
   оставить пустым иначе).
3. **Ошибка неверных данных** — явное сообщение "Check Point rejected
   these credentials" с призывом проверить host/username/password/domain,
   без утечки исходных данных в лог.
4. **После первого успешного подключения** — сайдбар показывает
   подключение и кнопки навигации к Access Control / Objects / Gateways /
   Health audit; секция подключения остаётся доступной ниже для
   переподключения с другими данными.
5. **Publish/Discard осведомлённость** — после любой write-операции
   (add-host, set-access-rule, ...) в ответе явно указывается, что
   изменение находится в текущей сессии и требует `publish_changes`,
   чтобы стать видимым остальным пользователям/API — это НЕ автоматика,
   пользователь должен явно попросить опубликовать.
6. **Disconnect** — только через единую кнопку "App settings" в сайдбаре,
   не дублируется рядом с формой подключения.
7. **Ошибка истёкшей сессии** — коннектор сам перелогинивается один раз
   прозрачно; если это тоже не удаётся — явное сообщение "Check Point
   session expired and re-login failed. Check your credentials are still
   valid.", без технического жаргона (sid/401) в первом слое сообщения.

## 3. Что НЕ должно происходить

- Никакого автоматического `publish` после каждого write-инструмента —
  это меняет то, что реально применяется к продакшену, без явного
  запроса пользователя.
- Никакого автоматического `install-policy` после `publish` — это
  отдельное, ещё более взрывоопасное действие (реально разворачивает
  политику на боевые gateways), требует отдельного явного вызова.
